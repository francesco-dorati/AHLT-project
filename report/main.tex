\section{Introduction}
\subsection{Context and objective}
This project is based on SemEval-2013 Task 9 (biomedical information extraction).
Task 1 is \textbf{Named Entity Recognition and Classification (NERC)}: identify drug mentions and classify them into the provided entity types.

\subsection{Task 1 deliverables}
The Task 1 report requires documenting experiments and best results for:
\begin{itemize}
    \item System 1.1: NERC with feature-based Machine Learning (features, algorithms, hyperparameters).
    \item System 1.2: NERC with Neural Networks (input representations, architecture variants, hyperparameters).
    \item System 1.3: NERC with LLMs (prompt adaptation, few-shot, fine-tuning).
\end{itemize}
and a final comparison (effort, computational cost, explainability/controllability, and performance).

\section{Data, evaluation, and reproducibility}

\subsection{Dataset}
The dataset comes from the DDI Extraction 2013 shared task (SemEval-2013 Task~9). It consists of biomedical texts annotated with drug entity mentions. Each entity is classified into one of four types:

\begin{itemize}[nosep]
    \item \textbf{drug}: approved generic drug names (e.g., \textit{aspirin}, \textit{ibuprofen}).
    \item \textbf{brand}: commercial/trade names (e.g., \textit{Advil}, \textit{Tylenol}).
    \item \textbf{group}: pharmacological drug classes (e.g., \textit{NSAIDs}, \textit{opioids}).
    \item \textbf{drug\_n}: unapproved or experimental substances.
\end{itemize}

The data is split into three XML files:

\begin{table}[H]
\centering
\begin{tabular}{l r r}
\hline
\textbf{Split} & \textbf{Sentences} & \textbf{Entities} \\
\hline
Train  & 5{,}343 & 11{,}452 \\
Devel  & 1{,}477 & 3{,}125 \\
Test   & 1{,}455 & 3{,}228 \\
\hline
\end{tabular}
\caption{Dataset statistics.}
\label{tab:dataset}
\end{table}

\subsection{Evaluation protocol}
The task is formulated as \textbf{BIO sequence labeling}: each token is tagged as \texttt{B-}\textit{type} (beginning of an entity), \texttt{I-}\textit{type} (inside), or \texttt{O} (outside). The provided evaluator reconstructs entity spans from these tags and computes precision, recall, and F1 at the entity level. An entity is correct only if \emph{both} its span boundaries and its type match the gold standard (strict evaluation).

The evaluator reports two averages: \textbf{macro-averaged F1} (M.avg), which averages F1 across the four entity types equally, and \textbf{micro-averaged F1} (m.avg), which pools all predictions. Since the type distribution is heavily skewed (\textit{drug} accounts for $\sim$67\% of entities), macro-average is more sensitive to rare types like \textit{drug\_n}. Throughout this report, ``F1'' refers to \textbf{macro-averaged F1} (M.avg), as this is the primary metric reported by the evaluator.

\subsection{Reproducibility}
All code is in \texttt{code/1.1.NERC-ML/}. The pipeline is driven by \texttt{bin/run.py}, which supports three steps: \texttt{extract} (feature extraction), \texttt{train}, and \texttt{predict}. Feature toggles are controlled by boolean flags at the top of \texttt{bin/extract\_features.py}.

Hyperparameter sweep results are stored in \texttt{hyperparameter\_results\_mod*.csv}. Test evaluation scripts are \texttt{run\_best\_on\_test.sh} and \texttt{run\_mod8\_fast.sh}.

\section{System 1.1 — NERC with Machine Learning}
% ============================================================

\subsection{Baseline}
The baseline system uses minimal token-level features: the word form, its lowercase version, suffixes (3 and 4 characters), and simple boolean flags (uppercase, title case, digit, contains dash/digit). Context features are limited to the immediate previous and next tokens. The baseline also checks single-token dictionary membership against an external drug lexicon.

Three classifiers are compared throughout:
\begin{itemize}[nosep]
    \item \textbf{CRF}: Conditional Random Fields (\texttt{pycrfsuite}), which model label sequences.
    \item \textbf{SVM}: Support Vector Machine (\texttt{sklearn.svm.SVC}), token-level classification.
    \item \textbf{MEM}: Maximum Entropy / Logistic Regression (\texttt{sklearn.linear\_model.LogisticRegression}).
\end{itemize}

Baseline devel results (default hyperparameters): CRF~67.9\%, SVM~67.1\%, MEM~65.5\%.

We incrementally added nine groups of features. Each modification was evaluated on the devel set with default hyperparameters. Table~\ref{tab:feature-mods} summarizes the modifications and Figure~\ref{fig:feature-evolution} shows the progression.

\textbf{Key observations:}
\begin{itemize}[nosep]
    \item Mod~6 (biomedical patterns) gave the largest single improvement for CRF: +0.4 points.
    \item Mod~4 (context POS) unexpectedly \emph{hurt} CRF ($-$0.4 pts), likely due to feature space explosion with limited data. Reverting to mod~3 context and expanding the window ($\pm$2) in mod~5 was more effective.
    \item Mod~8 (multi-token spans) hurt CRF on devel but later proved beneficial on test (see Section~\ref{sec:test-eval}).
    \item MEM was insensitive to most feature additions, suggesting it struggles with the high-dimensional sparse feature space.
\end{itemize}

On the devel set, CRF consistently outperformed SVM and MEM across all feature configurations. However, this ranking did \emph{not} hold on the test set (Section~\ref{sec:test-eval}), highlighting the importance of final evaluation on held-out data.

\subsection{Hyperparameter experiments}

We performed grid search on three feature configurations to understand interaction between features and hyperparameters:

\begin{itemize}[nosep]
    \item \textbf{mod6}: additions 1--6 (no char n-grams, no spans, no long affixes)
    \item \textbf{mod8}: additions 1--8 (includes char n-grams and multi-token spans)
    \item \textbf{mod9\_wo8}: additions 1--7 + 9 (char n-grams and long affixes, no spans)
\end{itemize}

\textbf{CRF} was tuned over $c_1 \in \{0.01, 0.1, 0.5, 1.0\}$, $c_2 \in \{0.1, 0.5, 1.0, 5.0\}$, and max iterations $\in \{50, 100, 200, 500\}$ (64 configurations per feature set).

\textbf{SVM} was tuned over $C \in \{0.1, 1.0, 10.0, 100.0\}$ and kernel $\in \{\text{linear}, \text{rbf}, \text{poly}\}$.

\textbf{MEM} was tuned over $C \in \{0.01, 0.1, 1.0, 10.0, 100.0\}$.

Figure~\ref{fig:crf-heatmap} shows the CRF hyperparameter landscape on mod6 (best devel feature set).

\begin{figure}[H]
    \centering
    \includegraphics[width=0.55\linewidth]{fig_crf_heatmap.pdf}
    \caption{CRF devel F1 as a function of $c_1$ and $c_2$ (mod6, best iteration per cell). Low $c_1$ with low $c_2$ yields the best results. Performance is relatively stable across the grid ($\pm$1\%).}
    \label{fig:crf-heatmap}
\end{figure}

\textbf{Key findings from hyperparameter tuning:}
\begin{itemize}[nosep]
    \item CRF: low regularization ($c_1 \leq 0.1$, $c_2 \leq 0.5$) with few iterations (50) works best. The model converges quickly.
    \item SVM: rbf kernel with $C = 0.75$--$1.0$ and default $\gamma$ (\texttt{scale}) is optimal. Manually setting $\gamma$ consistently hurts and can make training extremely slow (hours per run).
    \item MEM: completely insensitive to hyperparameters --- F1 stays at $\sim$66\% regardless of $C$ or iterations.
    \item The scores are tightly clustered within each model type ($<$1\% spread), meaning \textbf{the feature set matters more than hyperparameter tuning}.
\end{itemize}

\textbf{Discussion:}
\begin{itemize}[nosep]
    \item \textbf{CRF mod8 is the best model} (68.2\% test F1), but the gap to SVM and MEM on mod8 is small ($<$0.5\%).
    \item \textbf{Multi-token dictionary spans (addition~8) are key for generalization.} They hurt CRF on devel ($-$0.8 pts) but improved test performance across all classifiers. This suggests they help the model learn patterns that transfer better to unseen data.
    \item \textbf{Overfitting on devel}: CRF with mod6/mod9 features scored 68.3--68.5\% on devel but only 62--63\% on test. The likely cause is that the rich subword features (char n-grams, long affixes) overfit to devel-specific token distributions. The multi-token spans in mod8 act as a form of regularization by providing higher-level dictionary evidence.
    \item \textbf{All three classifiers are competitive on mod8}: CRF~68.2\%, SVM~67.9\%, MEM~67.8\%. This indicates that the feature engineering is the dominant factor, not the classifier choice.
\end{itemize}

\subsection{Context}
Agriculture monitoring increasingly relies on aerial imagery to assess crop health, vegetation density, and irrigation practices over large areas. \subsection{Objective}
The objective of this homework is to build an image-processing segmentation pipeline (restricted to techniques from this week: histogram analysis and thresholding) that produces a \textbf{binary mask} isolating irrigated olive grove areas from the non-irrigated background.

In our approach, we:
\begin{enumerate}
    \item enhance vegetation using the \textbf{Excess Green Index (ExG)} computed from RGB channels,
    \item select a threshold (using \textbf{Otsu} on the ExG distribution) to obtain an initial binary mask,
    \item apply simple \textbf{morphological post-processing} to clean noise and fill small gaps,
    \item evaluate results using a manually created \textbf{Ground Truth} mask and the \textbf{Intersection over Union (IoU)} metric.
\end{enumerate}

\section{Segmentation Pipeline}
\label{sec:pipeline}
\subsection{Vegetation Index: Excess Green (ExG)}
The first step of the pipeline is to highlight vegetation using a simple index derived from RGB values. Since irrigated olive groves contain denser green vegetation than the arid background, we compute the \textbf{Excess Green Index (ExG)} per pixel:

\begin{equation}
\mathrm{ExG} = 2g - r - b
\end{equation}

where $r, g, b$ are the red, green and blue channels, respectively (normalized to the range $[0,1]$). The factor $2g$ emphasizes the green component, while subtracting $r$ and $b$ suppresses bright soil and residues. As a result, vegetation tends to have higher ExG values than the surrounding terrain.

In practice, the input image is loaded in RGB, converted to floating point, and ExG is computed using a direct per-pixel formula. The following snippet is taken from \texttt{segmentation\_step1.py}:

\begin{minted}[fontsize=\small, linenos]{python}
image = Image.open(image_path).convert("RGB")
rgb_uint8 = np.asarray(image)
rgb = rgb_uint8.astype(np.float32) / 255.0

r = rgb[..., 0]
g = rgb[..., 1]
b = rgb[..., 2]

exg = 2.0 * g - r - b
\end{minted}

\subsection{Thresholding (Otsu / Manual)}
To obtain a binary segmentation from the ExG map, we apply a global threshold $T$ and classify pixels as vegetation when:

\begin{equation}
\text{mask}(x,y) = \begin{cases}
1 & \text{if } \mathrm{ExG}(x,y) \geq T \\
0 & \text{otherwise}
\end{cases}
\end{equation}

In this homework we use \textbf{Otsu's method} to automatically select $T$ from the ExG histogram. Otsu selects the threshold that maximizes the \emph{between-class variance} (equivalently, it finds the split that best separates two classes in the 1D distribution).

The following snippet (from \texttt{segmentation\_step1.py}) shows the thresholding step and the creation of the initial binary mask:

\begin{minted}[fontsize=\small, linenos]{python}
threshold = otsu_threshold(exg)
mask = exg >= threshold
\end{minted}

\subsection{Post-processing (Morphology and Cleaning)}
The raw masks obtained by a single global threshold (Figure~\ref{fig:raw-masks}) may contain small isolated pixels, small holes inside tree blobs, and fragmented regions. To improve the visual quality of the segmentation while staying within classical image processing techniques, we apply a lightweight post-processing step:

\begin{itemize}
    \item \textbf{Opening} (erosion followed by dilation) with a small square structuring element to remove small noise.
    \item \textbf{Closing} (dilation followed by erosion) to fill small gaps and connect fragmented vegetation blobs.
    \item \textbf{Small component removal} to discard connected components below a minimum size threshold.
\end{itemize}

In our implementation we use kernel sizes $3\times 3$ for opening and $5\times 5$ for closing, and we remove connected components smaller than 200 pixels. The key operations (from \texttt{segmentation\_step1.py}) are shown below:

\begin{minted}[fontsize=\small, linenos]{python}
opened = binary_open(mask, k=3)
closed = binary_close(opened, k=5)
cleaned = remove_small_components(closed, min_size=200)
\end{minted}

\section{Evaluation and Error Measurement}
\label{sec:evaluation}
\subsection{Intersection over Union (IoU)}
To quantitatively assess segmentation quality, we compare each predicted binary mask against its corresponding Ground Truth (GT) mask using the \textbf{Intersection over Union (IoU)} metric (also called the Jaccard index). For a predicted foreground set $P$ and GT foreground set $G$ (foreground = irrigated vegetation), IoU is defined as:

\begin{equation}
\mathrm{IoU}(P, G) = \frac{|P \cap G|}{|P \cup G|}
\end{equation}

where $|\cdot|$ denotes the number of foreground pixels. IoU ranges from 0 to 1: a value of 1 corresponds to perfect overlap, while 0 indicates no overlap.

In this report, $P$ is the \textbf{final cleaned mask} produced by the pipeline (Section~\ref{sec:pipeline}), and $G$ is the manually created GT mask (Section~2.2). The IoU values are computed per image and summarized in the next subsection.

\section{Implementation}
\subsection{Code Structure}
The implementation is organized as two small Python scripts:

\begin{itemize}
    \item \textbf{Segmentation pipeline:} \texttt{segmentation\_step1.py}. This script loads each input RGB image, computes the ExG map, applies Otsu thresholding, performs morphological cleanup, and saves the intermediate and final visual outputs.
    \item \textbf{Evaluation:} \texttt{segmentation\_eval\_iou.py}. This script recomputes the final prediction masks, loads the manual GT masks (\texttt{gt1.png}, \texttt{gt2.png}, \texttt{gt3.png}), computes IoU, and saves a CSV summary plus TP/FP/FN error maps.
\end{itemize}

The workspace uses the following folders for outputs:
\begin{itemize}
    \item \texttt{outputs\_step1/}: ExG visualizations and histograms, raw masks, cleaned masks, and red overlay images.
    \item \texttt{outputs\_eval/}: IoU results in \texttt{iou\_results.csv}, and evaluation visualizations (error maps and overlays).
    \item \texttt{report/}: LaTeX report source (\texttt{main.tex}), compiled PDF, and a copy of the figures with LaTeX-safe filenames.
\end{itemize}

All scripts are designed to run with Python 3 and standard scientific packages used in this homework (NumPy, PIL/Pillow, Matplotlib).

\section{Conclusion}
This homework implemented a classical image-processing pipeline to segment irrigated olive groves from RGB aerial imagery using only techniques from this week (histogram analysis and thresholding).

The proposed approach combines (i) a vegetation-sensitive ExG index, (ii) a global Otsu threshold to obtain an initial binary mask, and (iii) lightweight post-processing (opening/closing and small-component removal) to produce cleaner and more spatially coherent predictions. Qualitatively, the red-overlay visualizations show that the segmented regions follow the regular orchard texture and canopy layout.

Quantitatively, IoU evaluation against manually created GT masks shows a strong dependence on scene conditions and annotation details: the method performs best on the second image, while performance drops on the first and third images where illumination changes, shadows, or background-green responses make global thresholding less reliable.
